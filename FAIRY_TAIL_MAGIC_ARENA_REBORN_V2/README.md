# FAIRY TAIL : MAGIC ARENA — REBORN v0.2

**비공식 개인 학습용 팬게임 | 2–4인 온라인 도트 액션 대전**

이 버전은 기존 V1 온라인 서버를 기반으로 **그래픽과 전투 형식을 크게 변경한 실제 실행용 리빌드**입니다. 기존의 위에서 내려다보는 구도를 버리고 횡스크롤 격투 게임 스타일의 고정 스테이지로 변경했습니다. 원작 제작사와 무관한 비공식 프로젝트입니다.

## 이번 리빌드에서 실제로 바뀐 것

- 손으로 디자인한 4명 캐릭터의 **도트 스프라이트 36프레임**: 각 캐릭터별 `idle1`, `idle2`, `run1`, `run2`, `jump`, `attack`, `cast`, `hurt`, `victory` 9개 이미지
- 캐릭터 선택 화면: 애니메이션 스타일의 얼굴 초상화 4장 + 도트 미리보기 + 고유 직업 설명
- 마그놀리아 길드 광장 테마 **1280×720 픽셀 아트 스테이지**
- 전투 화면: 상대별 초상화, HP/MP바, 중앙 라운드 타이머, 플레이어 이름표, 피격/스킬 이펙트, 마법 커맨드 HUD
- **횡스크롤 격투 조작**: 좌우 이동, 점프, 가드, 회피 대시, 기본공격, 캐릭터별 고유 마법/궁극기
- 기존 서버의 1대1, 1대1대1, 2대2 온라인 방, 팀 구분, 친구 초대, 채팅, 서버 판정, 타이머/승패/재대결 유지
- 서버에서 점프, 중력, 대시 재사용 대기시간, 가드 피해 감소 등 판정
- 모바일 터치 버튼(시범 지원) / 데스크톱 플레이 최적화

캐릭터 초상화는 AI로 제작한 비공식 애니메이션풍 팬아트입니다. 원작 애니메이션 장면을 그대로 캡처한 이미지는 아닙니다. 캐릭터 스프라이트는 고품질 상용 격투 게임의 모든 중간 프레임을 구현한 것이 아니라, **캐릭터당 주요 동작 9장으로 구성한 플레이 가능한 첫 번째 아트 리빌드**입니다.

## Windows에서 바로 실행하기

1. [Node.js](https://nodejs.org/) 20 이상을 설치합니다.
2. 프로젝트 폴더 안에서 **`START_WINDOWS.bat` 더블클릭** (또는 터미널에서 `npm start`).
3. PC Chrome/Edge에서 **`http://localhost:3000`** 접속.
4. 브라우저 창을 두 개 열어 각각 다른 닉네임으로 접속합니다.
5. 첫 번째 창: **새로운 대전방 만들기** → 6자리 방 코드 확인.
6. 두 번째 창: **방 코드 입력 / 입장** → 첫 번째 창 방장이 **대전 시작** 클릭.
7. 3인 또는 4인 모드를 확인하려면 그만큼 창/친구가 필요합니다.

> HTML 파일을 직접 더블클릭하면 온라인 접속이 동작하지 않습니다. **Node.js 서버를 실행해야 합니다.** 별도 npm 패키지 설치는 필요 없습니다.

### 조작법

| 키 | 동작 |
|---|---|
| `A / D` 또는 `← / →` | 좌우 이동 |
| `W`, `SPACE`, `↑` | 점프 |
| `S`, `↓` | 누르고 있는 동안 가드 (받는 피해 감소) |
| `SHIFT` | 바라보는 방향으로 회피 대시 (쿨타임 존재) |
| `J` 또는 캔버스 마우스 왼쪽 클릭 | 기본 공격 |
| `Q / E / R` | 고유 마법 스킬 |
| `F` | 궁극기 (게이지 100% 필요) |
| `ENTER` | 채팅 입력 |

상대와 마주 보는 방향은 좌우 이동으로 정합니다. 마법은 캐릭터가 바라보는 방향으로 발사합니다. 모바일 터치 버튼은 작은 화면에서 조작이 제한적일 수 있습니다.

## 기존 GitHub + Render 온라인 서버를 교체하는 방법

**기존 버섯숲 RPG의 저장소나 서버는 건드리지 마세요.** 페어리테일 게임용 GitHub 저장소와 Render Web Service만 업데이트합니다.

1. 먼저 이 ZIP 파일의 압축을 풉니다.
2. 기존의 `fairy-tail-magic-arena` GitHub 저장소에 들어가 **새 프로젝트의 내용물**을 올립니다. `server.js`, `game.js`, `public/index.html`, `public/game-client.js`, `public/style.css`, `public/assets/sprites/`, `public/assets/portraits/`, `public/assets/stages/` 등을 포함해야 합니다. 외부 폴더를 통째로 한 단계 더 중첩하지 마세요.
3. GitHub의 `Commit changes`로 변경을 확정합니다. 대체 파일 업로드가 어려우면 별도 새 저장소를 만들고 기존 페어리테일 서비스와 구분되는 새 Render 서비스를 만들 수도 있습니다.
4. 기존 Render 페어리테일 서비스의 자동 배포가 활성화되어 있으면 최신 커밋이 자동 배포됩니다. 그렇지 않으면 Render **Deploys → Manual Deploy → Deploy latest commit**을 누르세요.
5. Render에서 `Live`를 확인하고 기존 페어리테일 게임 주소로 접속합니다. 이전 화면이 보이면 브라우저에서 `Ctrl+Shift+R` 새로고침을 해보세요.
6. 기존 저장소에서 `package.json`이 `fairy_tail_magic_arena_reborn` 같은 하위 폴더에 있다면, Render **Settings → Root Directory**에 실제 위치를 지정해야 합니다. 최상위에 있다면 비워둡니다.

새 Render 서비스로 처음 배포할 때는 **Language: Node / Region: Singapore / Build: `npm install` / Start: `npm start` / Compute: Free**를 선택합니다. `render.yaml`은 동일 설정의 Blueprint 용도입니다. 기존 무료 서버는 유휴 상태에서 절전될 수 있습니다.

## 원작 한국어 더빙 음성과 전투 OST

오디오 자동 재생 연결부는 포함했지만 **저작권 있는 원곡 및 성우 원본 음성 파일은 포함되어 있지 않습니다.** 사용 권한이 있는 파일을 다음 경로에 넣을 수 있습니다.

- 전투 테마: `public/assets/audio/battle-theme.mp3`
- 나츠: `public/assets/audio/voices/natsu/attack.mp3`, `skill-q.mp3`, `skill-e.mp3`, `skill-r.mp3`, `ultimate.mp3`
- `lucy`, `erza`, `gray` 폴더에도 같은 파일명 5개씩

파일을 넣고 GitHub에 커밋하면 배포 후 클라이언트가 자동 재생을 시도합니다. 브라우저 정책 때문에 사용자가 방 입장 버튼 등을 클릭해야 오디오가 활성화됩니다.

## 테스트

```bash
npm test
```

현재 자동화 테스트는 **15개**이며 방 생성/입장/전투/팀전/채팅/점프/가드/대시 등 서버 규칙과 네트워크 연결을 검증합니다. 로비 및 전투 미리보기 이미지는 브라우저 렌더링을 위해 **모의 플레이어 상태**를 넣어 만든 시각 검증 화면입니다. 실제 서로 다른 지역의 실사용자 간 지연·호환성·다양한 기기 조작 테스트까지 완료했다는 뜻은 아닙니다.

## 현재의 한계

- 현재는 기능과 그래픽을 모두 갖춘 **초기 리빌드 버전**입니다. 상용 격투게임 수준의 수십~수백 장 캐릭터 모션과 스테이지 아트, 넉백/연계기/히트스톱/콤보 UI, 고급 네트워크 보정은 추후 개선이 필요합니다.
- 캐릭터 선택 초상화는 원작 컷의 정확한 복사본이 아닌 AI 기반 팬아트입니다.
- 원작 더빙 및 메인 테마 파일 미포함.
- 로그인/세이브/랭킹/매치메이킹/영구 보관 기능 없음. 방 정보는 메모리에만 있고 서버 재시작 시 초기화됩니다.
- 실시간 동기화는 서버 판정 기반이지만 보간·지연 보상·서버 보안은 상용 수준이 아닙니다.
- 게임은 PC 브라우저를 중심으로 테스트했습니다. 모바일 조작 버튼은 실험적 지원입니다.

**아트 수정:** 캐릭터 그림은 `public/assets/sprites/`에서 직접 교체할 수 있습니다. 각 캐릭터 9개 파일명과 이미지 비율을 유지하면 자동 반영됩니다. 생성 스크립트는 `tools/build_art.py`에 있으며, 기존 동작/디자인을 수정한 후 스프라이트를 다시 만들 수 있습니다. 초상화는 별도 이미지 리소스를 유지합니다.
